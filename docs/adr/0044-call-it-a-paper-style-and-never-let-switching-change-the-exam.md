# Call it a Paper Style, and never let switching one change the Exam

Teachers ask for papers that look like the ones they already use, and the requests differ mostly in presentation: how Parts are labelled, fonts, the header and footer, where points appear, a cover page, the paper size. ADR-0041's Question Style already chose how questions print from one Exam-wide preset. Its name no longer fits once a style also decides a paper's cover, its running furniture and its page size, which are not about questions.

**Question Style is renamed Paper Style**, and a test now has three layers: its Question Banks say what is asked, its Exam says which Questions in what order and arrangement and the Paper Details (ADR-0045) that are its own, and its Paper Style says how all of it is drawn. Exam Record `0.4.0` had not shipped when this was decided, so its `questionStyle` member becomes `paperStyle` with no compatibility reader.

- **A Paper Style is data Test Parrot draws, never code.** Letting teachers or third parties supply rendering packages that draw their own paper was considered, since every school's format differs. It was rejected: print, PDF and DOCX must draw the same pages from one Layout Plan (ADR-0001), and a package that drew its own could not be held to that, nor run safely inside the app. A style is instead a set of rules the Export Document and Layout Plan read. When a format needs something no rule can describe — a working column beside each question, a marker's column in the margin, a score grid — that becomes a new layout capability every style may use, not a style of its own. Built-in styles are the only ones for now; describing them as data is what lets saved and shared styles follow without changing what an Exam stores.
- **An Exam stores a Paper Style's name, and switching never changes the Exam.** Storing every rule on the Exam, so a teacher could tweak one, was considered; storing the name is what makes Standard → Exam Board → Standard return the same paper. What the teacher set always wins over what a style supplies, and switching only changes what the teacher did not set:
  - **Work Space** already worked this way (ADR-0041). Exporting a package now always writes a Work Space the teacher set, a zero-height "None" included; it was dropped when the Exam's current style ruled no lines, so the position took lines again under a lining style after import. Picking None is stored the same way under every style, Standard included, so a position the teacher emptied under Standard is still empty under Classic; only a position the teacher never touched stores nothing.
  - **Word Bank layout** amends ADR-0041, which re-placed every Matching position over the teacher's flips whenever the Exam changed style. A position keeps a concrete layout, still decided once by the measured fit rule and never by a Layout Plan, but it also records whether the teacher chose it. Changing style re-places only the positions the teacher did not choose; the fit rule is deterministic, so switching back gives the same layouts. Exam Record `0.4.0` carries the choice as a Matching position's `wordBankLayoutSet`.
- **No Paper Style carries an exam board's name, points or wording.** A style may follow a board's conventions, which are common to many — bracketed points, dotted answer lines, `1 (a) (i)` — but is named for what it does, and every default it prints is Test Parrot's own text or the teacher's Paper Details. No logo, footer or instruction from a board's papers is reproduced.
